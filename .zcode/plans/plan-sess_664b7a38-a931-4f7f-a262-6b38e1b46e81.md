# Agent Memory 全链路实现规划

> 基于 7 轮讨论锁定的边界:**记忆管理集成进 desk 主体(像 Meeting,走 Source 流水线);采集头是独立薄 shim(各 agent hook 都指向它);agent 通过 MCP 自取记忆(pull,不注入);Handoff 走点对点模型**。

---

## 阶段总览与依赖关系

```
阶段1 地基     → 阶段2 Handoff闭环  → 阶段3 采集管线   → 阶段4 自动提炼  → 阶段5 MCP补齐
(Project+AgentType)  (实体+工具,可演示)   (Raw事件+Ingest+shim)  (Extractor)      (工具集对齐)
```

**设计原则:阶段 1+2 完成后,你画的 Codex→Claude handoff 闭环即可用**(agent 手动 `memory_capture` 记忆 + handoff 交接)。阶段 3+4 再补上自动采集和提炼,让记忆"自动长出来"。

## 阶段 4:Memory Extractor(自动提炼)

**目标**:从 Raw Events 自动提炼候选 MemoryItem(启发式先行,可选 LLM),500 事件 → 2~5 条记忆。

### 4.1 MemoryExtractorService
**文件**:`src/KnowledgeEngine.Infrastructure/AgentMemory/MemoryExtractorService.cs`(新建)

**触发**:SessionEnd 事件 / 定时后台扫描 completed session。

**启发式规则(先做,无 LLM 依赖)**:
1. 用户拍板/纠错处(user_prompt 含"就这样/确认/不对/应该")→ `decision` 候选
2. assistant 结论段(post_response 末尾含"总结/决定/结论")→ `decision`/`fact` 候选
3. PostToolUse Edit 摘要(file_modify 类)→ `what-changed` 候选
4. SessionEnd 摘要 → `summary` 候选
5. error→fix 序列(command 失败后续成功)→ `problem-solution` 候选

**提炼流程**:
```
Raw Events → 启发式命中点 → 提取内容 → MemorySanitizer 脱敏
  → MemoryAdmissionService.EvaluateAdmission(AdmissionState=Candidate)
  → ConflictDetectionService 查重(同 project+subject)
  → 冲突则 supersede,无冲突则入库
```
**复用现有**:`MemorySanitizer`、`MemoryAdmissionService`、`ConflictDetectionService`、`MemoryEmbeddingService`(向量化),全部已建。

- `DependencyInjection.cs`:注册 `MemoryExtractorService`

## 每阶段验收标准

| 阶段 | 验收 |
|---|---|
| **1** | 两个 agent profile(codex/claude)的 session 落到同一 ProjectId;`AgentType` 字段可读写 |
| **2** | Codex 调 `memory_handoff(to="claude")` → Claude 调 `memory_get_handoff` 领到 → `memory_complete_handoff` 写回 → Codex 查到结果。**你画的闭环走通** |
| **3** | shim 安装后,真实 Claude session 事件经 POST /ingest 入库为 Turn/Action;失败有 spool 重试 |
| **4** | 一个 100+ 事件的 session,SessionEnd 后自动产出 1~3 条 candidate MemoryItem,经 admission 入库 |
| **5** | `memory_search` 支持 types/agent/project 过滤;`memory_get`/`timeline`/`supersede` 可调 |

## 实施顺序建议

**先做阶段 1+2**(地基 + Handoff 闭环)——这是你明确要的协同能力,且依赖链最短,完成后即可演示 Codex↔Claude 交接。阶段 3+4(采集+提炼)是让记忆"自动长出来"的增强,可独立后续推进。阶段 5 是工具集打磨,随时可插。

每阶段都遵循现有约定:fluent 配置(`OnModelCreating`)+ `scripts/migrations/` 双 SQL 脚本 + `DependencyInjection.cs` 注册 + MCP `[McpServerToolType]` 自动发现。
