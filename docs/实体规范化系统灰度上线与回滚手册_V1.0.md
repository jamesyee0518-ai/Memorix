# Memorix 实体规范化系统灰度上线与回滚手册 V1.0

## 1. 目的与适用范围

本文用于指导实体规范化、去重、消歧、合并治理、搜索扩展和标准实体图谱从影子运行逐步进入生产。适用于 SQLite 本地模式和 PostgreSQL 云端模式。

上线原则：

- 数据库中的标准实体、别名、提及和合并审计是事实来源；
- 自动链接与自动合并使用独立开关；
- 初始阶段禁止自动合并；
- 每一阶段先观测、抽检和达标，再扩大范围；
- 错误合并通过撤销接口恢复，不直接修改数据库；
- 新表和审计数据在功能回退时保留。

## 2. 上线前检查

### 2.1 数据安全

- 备份业务数据库并验证备份可恢复；
- 记录数据库类型、版本、迁移版本和备份时间；
- 为每次存量任务生成独立批次 ID 和幂等键；
- 首批候选簇不超过 100 个；
- 确认执行账号具备实体治理权限，但普通只读用户不能执行合并、撤销或维护任务。

### 2.2 双数据库结构检查

SQLite 和 PostgreSQL 均需确认以下对象存在：

- 标准实体兼容字段和版本字段；
- 实体别名、提及、外部 ID、Embedding；
- 解析候选、治理任务、禁止合并；
- 合并日志、Outbox 事件；
- 工作区范围内的唯一索引和常用查询索引。

检查标准：

- 同一工作区的规范化名称与类型不会重复；
- 提及、别名和候选的外键可正确关联；
- 合并后旧实体 ID 可重定向到主实体；
- SQLite 升级可重复执行，PostgreSQL 迁移可正常应用。

### 2.3 基线验证

- 后端全量测试通过；
- 前端生产构建通过；
- 1,000 条 Golden Dataset 完整，其中 SAME 600 条、DIFFERENT 400 条；
- 版本边界、同名歧义、中英文与缩写样本各不少于 100 条；
- 旧实体读取、文档详情、搜索、问答和图谱基础功能无回归。

## 3. 功能开关初始值

```json
{
  "EntityResolution": {
    "Enabled": true,
    "ShadowMode": true,
    "EnableExactAliasLink": false,
    "EnableScoredAutoLink": false,
    "EnableLlmDisambiguation": false,
    "EnableAutoMerge": false,
    "EnableEntitySearchExpansion": false,
    "EnableGraphBackend": false
  }
}
```

`EnableAutoMerge` 必须保持关闭，直到人工合并、撤销、审计、Outbox 恢复和回滚演练全部通过。当前版本默认只支持人工确认后合并。

## 4. 灰度上线顺序

### 阶段 A：结构和影子运行

1. 发布数据库结构与兼容读取代码；
2. 开启 `Enabled` 和 `ShadowMode`；
3. 运行重复候选扫描，不改变已有实体归属；
4. 抽检提及证据、候选排序、硬阻断和工作区隔离；
5. 观察至少一个完整业务周期。

通过条件：

- 无跨工作区串数据；
- 重跑不重复创建提及、别名和候选；
- 影子任务可暂停、恢复、重试并显示进度；
- 错误和超时不会破坏原有实体关系。

### 阶段 B：确定性链接

1. 开启 `EnableExactAliasLink`；
2. 仅允许标准名、已验证别名和外部 ID 精确链接；
3. 先对单个工作区开放，再逐步扩大；
4. 每批结束后比较实体数、提及数、未解析数和文档关联数。

通过条件：

- 别名精确命中准确率不低于 99%；
- 版本边界没有自动错误链接；
- 不同流水线的重处理结果一致。

### 阶段 C：评分链接与 LLM 消歧

1. 开启 `EnableScoredAutoLink`，保持 `EnableAutoMerge=false`；
2. 先使用保守阈值，只自动链接高置信度提及；
3. 中置信度样本进入治理任务；
4. 确认本地 LM Studio 或云端模型可用后，再开启 `EnableLlmDisambiguation`；
5. 模型不可用、超时或证据不足时降级为待审核，不创建错误链接。

通过条件：

- Top-K 候选召回率不低于 95%；
- 自动链接准确率不低于 97%；
- 单提及规则解析 P95 不高于 800 ms；
- LLM 不能绕过类型冲突、版本边界和禁止合并等硬阻断。

### 阶段 D：人工合并治理

1. 在治理工作台查看候选和合并预览；
2. 先处理证据充分的高置信度重复实体；
3. 对明确不应合并的实体执行拒绝或永久阻断；
4. 每批合并后验证别名、提及、文档关联、候选、关系和旧 ID 重定向；
5. 抽取样本执行撤销演练。

通过条件：

- 合并数据库事务不超过 5 秒；
- 无重定向环路和关系自环；
- 旧 ID 可访问主实体；
- 撤销后实体、别名、提及、候选和关系可恢复；
- Outbox 失败不会回滚数据库合并，且可自动重试。

### 阶段 E：搜索、问答和图谱

1. 开启 `EnableEntitySearchExpansion`；
2. 验证中文、英文和缩写查询可召回同一标准实体相关文档；
3. 检查回答引用包含标准实体名与原始提及；
4. 开启 `EnableGraphBackend`；
5. 验证图谱节点、聚合关系和相关文章都使用标准实体 ID。

通过条件：

- 合并前后搜索、问答和图谱结果连续；
- 引用可以追溯到原始文档和分块；
- 引用实体一致性检查无严重错误；
- 点击图谱节点显示正确相关文章。

### 阶段 F：存量任务

按以下顺序执行维护任务：

1. `ALIAS_MIGRATION`：迁移旧别名；
2. `HISTORICAL_MENTION_BACKFILL`：补齐历史兼容提及；
3. `REDIRECT_COMPRESSION`：压缩旧 ID 重定向链；
4. `ENTITY_REINDEX`：重建实体相关索引。

每项任务都使用独立幂等键。先运行 100 条的小批次，验证后再增加批量。任务运行期间持续观察进度、失败原因和 Outbox 积压。

## 5. 质量门禁

| 指标 | 放量门槛 |
| --- | ---: |
| 实体提及抽取准确率 | ≥ 92% |
| 别名精确命中准确率 | ≥ 99% |
| Top-K 候选召回率 | ≥ 95% |
| 自动链接准确率 | ≥ 97% |
| 错误自动合并率 | ≤ 0.5% |
| 未解析提及率 | ≤ 15% |
| 人工审核一致率 | ≥ 95% |
| 合并撤销率 | ≤ 1% |
| 精确别名查询 P95 | ≤ 100 ms |
| Top-K 候选召回 P95 | ≤ 500 ms |
| 单提及规则解析 P95 | ≤ 800 ms |
| 1 万实体候选扫描 | ≤ 10 min |
| 合并数据库事务 | ≤ 5 s |

任一安全指标不达标时停止扩大范围。错误合并率和撤销率优先级高于自动化率。

## 6. 数据一致性核对

每批任务完成后，在相同工作区核对：

- 活跃实体数、已合并实体数；
- 别名总数与已验证别名数；
- 提及总数、已解析提及数与未解析提及数；
- `DocumentEntity` 聚合与逐条提及统计；
- 关系数量、自环数量和重定向链深度；
- 待审核候选和治理任务数量；
- Outbox 待处理、失败和最大等待时间；
- 全文、向量和图谱可检索实体数量。

目标：

- 自环数量为 0；
- 重定向链不超过系统限制，且不存在环；
- 文档聚合可以由提及数据重新计算得到；
- 数据库、搜索、问答和图谱对同一实体使用相同标准 ID。

## 7. 回滚流程

### 7.1 功能回退

按影响由大到小关闭：

1. `EnableAutoMerge`；
2. `EnableLlmDisambiguation`；
3. `EnableScoredAutoLink`；
4. `EnableExactAliasLink`；
5. `EnableEntitySearchExpansion`；
6. `EnableGraphBackend`；
7. 必要时关闭 `Enabled`。

保持数据库新表、合并日志、候选审计和 Outbox 数据，不执行删表。

### 7.2 任务止损

1. 暂停正在运行的治理或维护任务；
2. 记录任务 ID、批次 ID、幂等键、当前进度和最后错误；
3. 不直接修改任务状态或删除失败记录；
4. 修复原因后使用恢复或重试操作继续；
5. 重试前确认幂等逻辑不会重复写入。

### 7.3 错误合并恢复

1. 从合并历史定位合并记录；
2. 检查是否出现后续依赖合并或需要拆分；
3. 能安全撤销时，通过撤销接口恢复；
4. 返回“需要拆分”时转人工治理，不执行 SQL 逆向修改；
5. 撤销后触发实体重建索引并复查搜索、问答和图谱。

### 7.4 索引与 Outbox 恢复

1. 数据库合并事实保持不变；
2. 失败事件由 Outbox 自动重试；
3. 达到最大重试次数后记录失败原因并人工重试；
4. 大面积不一致时运行 `ENTITY_REINDEX`；
5. 索引重建完成后重新执行数据一致性核对。

## 8. 常见故障处理

| 故障 | 处置 |
| --- | --- |
| 重定向环路或链过深 | 关闭合并入口，运行重定向检查；确认审计后执行压缩任务 |
| Outbox 大量积压 | 停止扩大批次，检查索引服务；恢复后重试失败事件 |
| 未解析率突然升高 | 回退评分或 LLM 开关，检查模型、Prompt、术语和阈值版本 |
| 版本实体被错误链接 | 立即关闭评分链接，加入禁止合并，撤销错误合并并补充回归样本 |
| 工作区数据混入 | 停止所有写任务，关闭实体解析，按审计定位批次并恢复备份 |
| SQLite 升级失败 | 停止应用，保留原文件，使用备份验证升级脚本后再执行 |
| PostgreSQL 迁移失败 | 停止发布，按迁移工具记录处理；不要手工跳过结构版本 |
